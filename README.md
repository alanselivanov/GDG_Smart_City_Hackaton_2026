# Qala рядом

**Городской ИИ-помощник для прогулок по Астане.** Пользователь пишет, где находится и сколько у него времени. Приложение предлагает до трёх конкретных мест с пешим временем от точки старта, объяснением выбора, идеей занятия и ссылкой на источник. Если важных сведений нет, ответ показывает неопределённость.

Проект подготовлен для задачи НИЦ Smart City на хакатоне **Build with AI**. Целевая аудитория: жители и гости Астаны, которым нужен короткий план прогулки рядом с собой. Особый сценарий: турист перед вылетом, когда прогулка должна укладываться в запас времени до аэропорта.

## Что можно показать в демо

1. **Прогулка от Mega Silk Way.** Запрос «Я возле Меги, хочу погулять 2 часа пешком» определяет точку старта из текста, предлагает до трёх мест, показывает время пешком и карточки на карте.
2. **Семейный запрос.** «Еду с ребёнком — где рядом есть детские площадки или музей с интерактивами?» с геолокацией или выбранным стартом ищет подходящие категории. Интерактивность указывается как подтверждённая только при наличии данных источника.
3. **Перед вылетом.** «У меня 2 часа перед вылетом» с запасом прибытия в аэропорт 120 минут может вернуть пустой результат. Интерфейс объясняет расчёт, вместо того чтобы предлагать рискованную прогулку.

Есть дополнительные режимы: группа из 3–5 человек с разными стартовыми точками, фильтры категорий, требования к месту (например, тишина или розетки), выбор времени начала, русский, казахский и английский языки. Карта показывает точки и пеший путь к выбранному месту, если внешний сервис маршрутизации доступен. Результаты — **альтернативные отдельные остановки**, а не готовый маршрут из нескольких мест.

## Как это работает

```text
Запрос + точка старта + ограничения
        ↓
OSM/Overpass: автоматически собранный каталог POI в SQLite
2GIS Places: дополнительные кандидаты по текущему запросу (при наличии ключа)
        ↓
Смысловой поиск по embeddings + фильтры категории, атрибутов и времени
        ↓
Пешее время через Valhalla, проверка бюджета и часов работы
        ↓
Ранжирование кандидатов, затем проверяемое объяснение и действие
        ↓
1–3 карточки с источником, ограничениями и контекстом выбора
```

Это RAG-подход: модель работает с найденными сведениями о местах, а не придумывает каталог. Сервис сначала извлекает кандидатов, затем проверяет географические и временные ограничения. При доступном `LLM_API_KEY` embeddings помогают смысловому поиску, а модель может оценить кандидатов и написать текст. Сгенерированный текст проходит проверку по фактам карточки. Если API модели недоступен или проверка не пройдена, сервис использует поиск и объяснения на правилах. В ответе есть `context_used`, `generated_with`, `text_source` и ссылки `source_url`, чтобы отличать исходные данные от составленного текста.

Каталог OSM собирается скриптом `app.ingest` через Overpass, нормализуется и обновляется в SQLite. Обновление по умолчанию запускается раз в 24 часа; неудачная загрузка не стирает прошлый каталог. 2GIS не копируется в локальный каталог: его места добавляются к кандидатам во время запроса. `data/` не входит в Git: после клонирования Docker запускает импорт автоматически, а при локальном запуске его нужно выполнить вручную.



### Запуск для разработки

Нужны Python 3.10+ и Node.js 20.19+ или 22.12+. В корне проекта, PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
# Если .env ещё нет: Copy-Item .env.example .env
.\.venv\Scripts\python.exe -m app.ingest
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

Во втором терминале:

```powershell
cd frontend
npm ci
npm run dev
```

Откройте `http://localhost:5173`. Vite передаёт `/api` на локальный backend. Для Linux/macOS используйте `.venv/bin/python`.

## Сценарии проверки и ожидаемый результат

Перед ручной проверкой откройте `/api/health` на порту 8080 (или `/health` на порту 8000) и убедитесь, что `poi_count > 0`. Для геолокации браузер запрашивает разрешение только после нажатия кнопки. Число и названия мест зависят от свежести источников и времени поиска.

| Сценарий | Вход | Что проверить |
| --- | --- | --- |
| Прогулка у Mega Silk Way | «Я возле Меги, хочу погулять 2 часа пешком» | Старт распознан как Mega Silk Way; 1–3 карточки укладываются в бюджет, показывают «почему», занятие, пешее время и источник. |
| Тихое кафе | «Хочу тихое кафе с розеткой рядом», указать точку старта | Статус тишины и розеток основан на атрибутах источника; отсутствие подтверждения явно указано. |
| С ребёнком | «Где рядом площадка или интерактивный музей?», выбрать старт | Категория соответствует запросу; интерактивность не выдаётся за факт без данных. |
| Перед вылетом | «У меня 2 часа перед вылетом», указать старт и время рейса | Система учитывает дорогу до аэропорта и выбранный запас. Если времени не хватает, показывает причину отсутствия рекомендаций. |
| Вечером или ночью | Указать ночное время начала с часовым поясом и запрос об активности | Результаты учитывают планируемое время; неизвестные часы работы не превращаются в уверенное «открыто». |
| Группа | Три участника с разными координатами через режим группы | В карточке показано время пути участников; выбранное место укладывается в ограничения группы. |

Для API-запроса без браузера:

```powershell
$body = @{ query = 'Я возле Mega Silk Way, хочу погулять 2 часа пешком'; language = 'ru' } | ConvertTo-Json
Invoke-RestMethod -Uri http://localhost:8080/api/v1/recommendations -Method Post -ContentType 'application/json' -Body $body
```

Дополнительный список ручных шагов находится в `frontend/DEMO_SCENARIOS.txt`. Автоматические проверки: `python -m pytest -q` после установки `requirements-dev.txt`; сборка интерфейса: `cd frontend && npm run build`.

## Ограничения и безопасность

- Данные POI могут быть неполными или устаревшими. Часы работы, доступность, цены, события и удобства нужно проверять по ссылке на источник или у заведения. Статус «открыто» выводится только когда расписание можно интерпретировать; иначе показывается неопределённость.
- Пешее время и длительность визита являются оценками. Карточка считает путь **в одну сторону** и время на одной остановке. Карта может не построить линию маршрута при сбое Valhalla.
- В сценарии вылета опорная точка аэропорта взята из OSM и не подтверждена как вход в терминал. Запас до рейса настраивает пользователь; требования авиакомпании нужно проверить отдельно.
- Название или атрибут места не доказывают наличие конкретного события, блюда, розетки либо безбарьерного доступа. Неподтверждённые свойства помечаются в результате, а ошибочные ответы модели отбрасываются.
- Браузер получает геолокацию только по явному нажатию и держит её в памяти текущей страницы. Backend не ведёт отдельную таблицу истории запросов или координат пользователей. Для расчёта маршрута координаты передаются Valhalla, а при включённом 2GIS — его API; фронтенд также может отправить координаты Valhalla для линии на карте. Текст запроса и данные кандидатов передаются провайдеру модели при включённом `LLM_API_KEY`. Названия найденных стартовых мест кешируются в SQLite. Перед публичным развёртыванием нужны собственные условия хранения логов и политика приватности.

Источники данных: [OpenStreetMap / ODbL](https://www.openstreetmap.org/copyright) и, при включении, [2GIS Places API](https://docs.2gis.com/en/api/search/places/overview). Маршрутизация: Valhalla на данных OSM.
